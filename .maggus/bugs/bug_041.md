# Bug: Config not reloaded between daemon cycles — approval mode change has no effect until restart

## Summary

Switching from opt-in to auto-approve (or vice versa) while the daemon is running does not pick up features that became approved by the change. There are two compounding issues: the daemon uses a stale `wc.cfg` (loaded at startup) for approval decisions in every cycle, and when the daemon is idle it never wakes up because `config.yml` changes are filtered out of the fsnotify watcher.

## Steps to Reproduce

1. Set `approval_required: true` in `.maggus/config.yml`
2. Start the daemon (`maggus start`) with a feature that has no explicit approval entry
3. While the daemon is idle (waiting for work), change config to `approval_required: false`
4. Observe: the daemon does not wake up and does not start the feature
5. Even after the 30-second idle poll fires a cycle, the feature is still excluded because `wc.cfg` is stale

## Expected Behavior

Saving `config.yml` should wake the idle daemon (same as saving a feature file does), and the next cycle should start the newly-approved feature.

## Root Cause

**Issue 1 — stale config across cycles:**

`runSetup()` in `src/cmd/run_setup.go` loads the config once and stores it in `wc.cfg` (line 67):

```go
cfg, err := loadConfigFn(dir)
```

`runDaemonLoop()` in `src/cmd/daemon_keepalive.go` passes the same `wc` pointer to every call of `runOneDaemonCycle()` (line 104):

```go
hadWork, err := runOneDaemonCycle(cmd, wc, dir, runLogger, workCtx)
```

Inside `runOneDaemonCycle`, `buildApprovedPlans` (line 247) is called with `wc.cfg`:

```go
featureGroups, fgErr := buildApprovedPlans(dir, wc.cfg, featureStore, bugStore)
```

`buildApprovedPlans` in `src/cmd/run_loop.go:178` derives the approval mode from that stale config:

```go
approvalRequired := cfg.IsApprovalRequired()
```

`approval.Load(dir)` (line 174) is called fresh each cycle so approval entries are current — but the mode flag (`approval_required`) never updates.

**Issue 2 — config.yml not watched by fsnotify:**

The filewatcher in `src/internal/filewatcher/filewatcher.go` watches `.maggus/` but `isRelevantEvent` (line 205) only passes through `feature_approvals.yml`, `feature_*.md`, and `bug_*.md`. Changes to `config.yml` are silently discarded, so an idle daemon never wakes when the user edits the config.

## User Stories

### BUG-041-001: Reload config from disk at the start of each daemon cycle

**Description:** As a user, I want changing `approval_required` in the config file to take effect on the daemon's next cycle so I don't have to restart the daemon after tweaking approval settings.

**Acceptance Criteria:**
- [x] `runOneDaemonCycle` loads a fresh `config.Config` from disk via `loadConfigFn(dir)` instead of using `wc.cfg` for approval-related decisions
- [x] The fresh config is used when calling `buildApprovedPlans`
- [x] The fresh config is also passed into `OrchestratorConfig` fields that depend on config (e.g. `AutoContinue`, `OnComplete`, `Hooks`) so the entire cycle reflects the on-disk config
- [x] A feature that was unapproved under opt-in mode is picked up on the next cycle after the user switches to opt-out (auto-approve) mode
- [x] A feature previously running under auto-approve is not blocked after switching to opt-in mode mid-cycle (the orchestrator's existing between-feature re-check handles this)
- [x] No regression in `runOneDaemonCycle` behaviour when config is unchanged between cycles
- [x] `go vet ./...` and `go test ./...` pass

### BUG-041-002: Wake idle daemon when config.yml changes

**Description:** As a user, I want saving `config.yml` to wake the idle daemon immediately (same as saving a feature file does) so the config change takes effect without waiting for the 30-second poll.

**Acceptance Criteria:**
- [ ] `isRelevantEvent` in `src/internal/filewatcher/filewatcher.go` returns true for `config.yml` write/create events
- [ ] After saving `config.yml` while the daemon is idle, `waitForChanges` returns `wakeFileChange` and a new cycle starts
- [ ] Existing behaviour for `feature_*.md`, `bug_*.md`, and `feature_approvals.yml` events is unchanged
- [ ] `go vet ./...` and `go test ./...` pass
