# Bug: Run log JSONL entries missing task_id — completed task Output tab shows no data

## Summary

Tool use and output events written to `.maggus/runs/*.log` JSONL files don't include a `task_id` field. This means `loadCompletedTaskOutput()` in the status TUI can never match entries to a specific task — the Output tab for completed tasks always shows "No tool invocations yet" even when the log contains hundreds of entries.

## Steps to Reproduce

1. Run the daemon and let it complete a task
2. Open the status view, expand the feature, select the completed task
3. Switch to the Output tab
4. Observe: "No tool invocations yet" despite the task having run

## Expected Behavior

The Output tab for a completed task should show the full tool invocation history loaded from the run log.

## Root Cause

The run logger writes events without the `task_id` field. In `src/internal/runlog/runlog.go`, the `ToolUse()`, `Output()`, and `Info()` methods write JSONL entries with `maggus_id` (the feature UUID) but the `task_id` is either empty or not set.

The consumer — `scanLogForTask()` in `src/cmd/status_task_output.go:209-216` — filters entries by `entry.TaskID != taskID`. Since `TaskID` is always empty in the log entries, no entries match, and the function returns nil.

The fix: the run logger must include the current task ID in every tool_use, output, and info event. The `task_id` is already available — `ToolUse()` receives it as a parameter (`func (l *Logger) ToolUse(taskID, toolType string, params map[string]string)`), and `task_start`/`task_complete` events DO include it. Only the intermediate events (tool_use, output) fail to write it.

## User Stories
