# Bug: Feature output tab shows identical cost for every task

## Summary

In the feature output tab, every completed task displays the same `[$X.XX]` cost — specifically the cost of the last task that ran. The per-task cost values are all overwritten during log scanning, so no task shows its own individual cost.

## Steps to Reproduce

1. Run a feature with 3+ sequential tasks (e.g. `maggus work`)
2. After all tasks complete, open the feature output tab
3. Observe: every task line shows the same `[$X.XX]` amount (e.g. all show `[$3.61]`)

## Expected Behavior

Each task line should show the cost incurred by that specific task, not the cost of the last task to complete.

## Root Cause

The bug is in `src/cmd/status_task_output.go` at the fallback logic in `scanLogForTask` (lines 301–308):

```go
// task_usage events may lack TaskID but follow task tool_use entries.
if entry.TaskID != taskID {
    if entry.Event == "task_usage" && found {
        snap.TokenInput = entry.InputTokens
        snap.TokenOutput = entry.OutputTokens
        snap.TokenCost = entry.CostUSD   // BUG: overwrites cost with another task's value
    }
    continue
}
```

The comment describes a historic case where `task_usage` entries in the log might not carry a `TaskID`. This fallback was intended to pick up orphan `task_usage` events that follow a task's `tool_use` entries in the shared log. However, `task_usage` entries have carried a correct `TaskID` for a long time (set explicitly in `src/internal/runlog/runlog.go:229` via `TaskID: data.TaskID`, which is always populated from `tu.TaskShort` in `daemon_keepalive.go:362`).

Because the feature log is **shared across all tasks in a daemon run** (one log file per `runlog.Open` call, opened once in `daemon_keepalive.go:78`), a scan for task A encounters task B's and task C's `task_usage` events later in the file. Since `entry.TaskID != taskID` but `found == true`, the fallback overwrites the cost on every subsequent `task_usage` event — leaving every task with the cost of the last task's `task_usage` entry.

**Concrete example with 3 tasks, scanning for TASK-006-001:**

| Log entry | TaskID | found | Effect |
|-----------|--------|-------|--------|
| task_start | TASK-006-001 | → true | — |
| task_usage $0.42 | TASK-006-001 | true | cost = $0.42 ✓ |
| task_start | TASK-006-002 | true | skipped (continue) |
| task_usage $1.85 | TASK-006-002 | true | cost = $1.85 ← wrong! |
| task_start | TASK-006-003 | true | skipped (continue) |
| task_usage $3.61 | TASK-006-003 | true | cost = $3.61 ← wrong! |

All three tasks end up displaying `$3.61`.

## User Stories

### BUG-056-001: Fix task_usage fallback to ignore entries from other tasks

**Description:** As a user, I want each task in the feature output tab to display its own individual cost so I can see how much each task actually spent.

**Acceptance Criteria:**
- [ ] The fallback in `scanLogForTask` only accepts `task_usage` entries where `entry.TaskID == ""` (i.e. legacy entries with no TaskID), not entries belonging to a different task
- [ ] Each completed task in the feature output tab shows its own cost, not the cost of the last task
- [ ] A feature with tasks costing $0.42, $1.85, and $3.61 displays those three distinct values, not $3.61 three times
- [ ] No regression in the cost display for currently-running tasks (live snapshot path is unaffected)
- [ ] `go vet ./...` and `go test ./...` pass
